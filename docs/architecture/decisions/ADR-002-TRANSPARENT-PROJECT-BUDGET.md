# ADR-002: แสดงกรอบงบโครงการแบบแยกองค์ประกอบอย่างโปร่งใส

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-08-07
- ผู้ตัดสินใจ: Product Owner

## บริบท

ผลิตภัณฑ์ต้องช่วยให้ผู้ใช้เข้าใจว่าบ้านที่ต้องการควรเตรียมงบประมาณเท่าไร พร้อมสื่อสารคุณค่าของค่าออกแบบและบริการวิชาชีพโดยไม่ทำให้ผู้ใช้รู้สึกว่ามีค่าใช้จ่ายซ่อนอยู่ การแสดงเฉพาะยอดรวมจะตรวจสอบยาก ส่วนการแสดงเฉพาะค่าก่อสร้างทำให้ผู้ใช้วางแผนงบโครงการไม่ครบ

## การตัดสินใจ

ระบบจะแสดงงบประมาณเป็นองค์ประกอบแยกกัน ได้แก่:

1. ช่วงค่าก่อสร้างประมาณการ
2. ช่วงค่าออกแบบและบริการวิชาชีพ
3. ค่าใช้จ่ายที่อาจต้องเตรียมเพิ่มเติม โดยแยกสิ่งที่คำนวณได้กับสิ่งที่ยังไม่รวม
4. กรอบงบรวมของโครงการ เมื่อข้อมูลเพียงพอให้คำนวณได้อย่างรับผิดชอบ

## หลักการนำเสนอ

- ไม่ซ่อนค่าออกแบบไว้ในค่าก่อสร้าง
- อธิบายขอบเขตและคุณค่าของงานออกแบบควบคู่กับราคา
- ห้ามรวมรายการที่ยังไม่มีข้อมูลรองรับแล้วแสดงเป็นยอดที่ดูแม่นยำ
- ทุกช่วงราคาต้องระบุฐานการคำนวณ เวอร์ชันกฎราคา และ Disclaimer
- Free Preview ใช้ช่วงกว้าง ส่วน Full Project Report แสดงรายละเอียดขององค์ประกอบและสมมติฐานมากกว่า

## เหตุผล

- ผู้ใช้เข้าใจเงินที่ต้องเตรียมได้ครบกว่าการเห็นค่าก่อสร้างเพียงรายการเดียว
- ทำให้ค่าออกแบบมีเหตุผลและตรวจสอบคุณค่าได้
- เพิ่มความน่าเชื่อถือและลดความรู้สึกว่าระบบเป็น Lead Trap
- รองรับการเปลี่ยนกฎราคาแต่ละองค์ประกอบโดยไม่กระทบกันทั้งหมด

## ผลตามมา

- Domain Model ต้องแยก Construction Estimate, Design & Professional Fee และ Additional Budget Items
- Pricing Engine ต้องส่งคืนช่วงราคา สมมติฐาน รายการที่รวม และรายการที่ไม่รวม
- Report ต้องไม่เรียกยอดใดว่า “ราคาสุดท้าย” หรือ “ใบเสนอราคา”
- ค่าใช้จ่ายที่ขึ้นกับการสำรวจ เช่น งานปรับสภาพดิน ต้องแสดงเป็นข้อควรเผื่อหรือรายการรอตรวจสอบ หากยังไม่มีข้อมูลเพียงพอ

## ตัวเลือกที่ไม่เลือก

- แสดงยอดรวมก้อนเดียวและซ่อนรายละเอียดจนกว่าจะปลดล็อก: ปฏิเสธเพราะลดความโปร่งใส
- แสดงเฉพาะค่าก่อสร้าง: ปฏิเสธเพราะไม่ตอบโจทย์การวางกรอบงบโครงการและลดคุณค่าของบริการออกแบบ
