# ADR-001: จำกัดขอบเขต MVP ไว้ที่บ้านสร้างใหม่

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-08-07
- ผู้ตัดสินใจ: Product Owner

## บริบท

Blueprint เดิมเปิดให้เลือกบ้านใหม่ รีโนเวต และต่อเติม แต่การประเมินราคารีโนเวตหรือต่อเติมจำเป็นต้องทราบสภาพอาคารเดิม โครงสร้าง งานระบบ ความเสียหาย ข้อจำกัดหน้างาน และข้อมูลจากการสำรวจมากกว่างานบ้านใหม่ หากใช้คำถามและสูตรเดียวกัน ช่วงราคาจะกว้างหรือดูแม่นยำเกินข้อมูลที่มี

## การตัดสินใจ

MVP จะรองรับการจัด Requirement และการประเมินงบประมาณสำหรับ “บ้านสร้างใหม่” เท่านั้น

## เหตุผล

- ทำให้ Domain Model และ Pricing Engine มีขอบเขตชัดเจน
- ลดคำถามที่ไม่เกี่ยวข้องกับผู้สร้างบ้านใหม่
- ทำให้ช่วงราคาประเมินอธิบายและตรวจสอบกับสถาปนิกได้ง่ายกว่า
- ลดความเสี่ยงจากการสื่อสารราคางานรีโนเวตที่ต้องพึ่งการสำรวจอาคารจริง
- ช่วยให้ทีมเปิดตัวและเก็บข้อมูล Funnel ได้เร็วขึ้น

## ผลตามมา

- หน้า Landing และ Configurator ต้องระบุชัดว่าเครื่องมือนี้ใช้สำหรับบ้านสร้างใหม่
- ไม่แสดงตัวเลือก Renovation หรือ Extension ใน MVP
- หากผู้ใช้ต้องการรีโนเวตหรือต่อเติม ให้ใช้ช่องทางปรึกษาทั่วไปที่แยกจากผลประเมินราคา
- การเพิ่ม Renovation หรือ Extension ในอนาคตต้องมี Domain Model, Question Set, Pricing Rules, Disclaimer และ Analytics แยกต่างหาก

## ตัวเลือกที่ไม่เลือก

- รองรับทุกประเภทด้วยสูตรเดียว: ปฏิเสธเพราะความน่าเชื่อถือของราคาไม่เพียงพอ
- รองรับบ้านใหม่และให้รีโนเวตส่ง Brief โดยไม่แสดงราคา: เก็บไว้พิจารณาเป็นผลิตภัณฑ์หรือ Flow แยกในอนาคต
