# ADR-008: ใช้ Allowance แยกสำหรับรายการพิเศษที่กระทบงบสูง

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-08-07
- ผู้ตัดสินใจ: Product Owner

## บริบท

รายการพิเศษบางประเภททำให้งบก่อสร้างเปลี่ยนอย่างมีนัยสำคัญและไม่ควรถูกซ่อนอยู่ในราคาต่อตารางเมตร แต่การให้ผู้ใช้เลือกสเปกอุปกรณ์หรือรายละเอียดทางเทคนิคตั้งแต่ MVP จะทำให้ขั้นตอนซับซ้อนและสร้างความแม่นยำที่ไม่สอดคล้องกับข้อมูลช่วงเริ่มต้น

## การตัดสินใจ

MVP จะให้ผู้ใช้กดเลือก High-impact Special Features และแสดงงบเผื่อเป็นช่วงแยกจากค่าก่อสร้างพื้นฐาน รายการเริ่มต้นประกอบด้วย:

1. สระว่ายน้ำ
2. ลิฟต์โดยสารภายในบ้าน
3. ระบบ Smart Home
4. ระบบผลิตไฟฟ้าพลังงานแสงอาทิตย์
5. จุดชาร์จรถยนต์ไฟฟ้า
6. พื้นที่ Double Volume
7. กระจกหรือช่องเปิดขนาดใหญ่เป็นพิเศษ

แต่ละรายการสามารถถามข้อมูลเสริมเท่าที่จำเป็น เช่น ขนาดสระ จำนวนชั้นที่ลิฟต์ให้บริการ หรือระดับระบบ Smart Home โดยต้องคงรูปแบบที่กดเลือกง่าย

## หลักการคำนวณ

- Special Feature ใช้ `allowance_range` ไม่ใช้ราคาจุดเดียว
- ไม่รวม Allowance ไว้ใน Material Level Rate เพื่อป้องกันการคิดซ้ำ
- ช่วงราคาต้องมีแหล่งที่มา วันที่อ้างอิง เวอร์ชัน และผู้อนุมัติ
- หากข้อมูลยังไม่พอ ให้แสดง “รอสถาปนิกประเมิน” หรือขยายช่วงราคา ไม่สร้างค่าประมาณที่ดูแม่นยำเกินจริง
- Allowance สามารถเปลี่ยนตามจังหวัด ขนาด ระดับวัสดุ หรือความซับซ้อนได้เมื่อมีข้อมูลรองรับ
- การเลือก Double Volume หรือกระจกขนาดใหญ่ต้องเชื่อมกับ Complexity Model เพื่อป้องกันการคิดต้นทุนซ้ำ

## หลักการ UX และ Report

- แสดงผลกระทบต่องบประมาณใกล้กับตัวเลือกแต่ไม่ใช้ถ้อยคำรับประกันราคา
- Summary แยก “ค่าก่อสร้างพื้นฐาน” และ “งบเผื่อรายการพิเศษ”
- Full Report อธิบายสมมติฐานของแต่ละ Allowance และรายการที่ยังต้องยืนยัน
- Free Preview แสดงว่ามีรายการพิเศษใดถูกเลือกและรวมผลเป็นช่วงกว้าง แต่ไม่เปิด Detailed Pricing รายรายการ
- Public Preview สามารถแสดงไอคอนหรือชื่อฟีเจอร์ที่ไม่เป็นข้อมูลส่วนตัว แต่ไม่แสดงราคาละเอียด

## เหตุผล

- ทำให้ราคาประเมินใกล้ความต้องการจริงมากกว่าการใช้ราคาต่อตารางเมตรอย่างเดียว
- รักษาประสบการณ์แบบกดเลือกง่าย
- ช่วยให้ผู้ใช้เห็นว่างบเพิ่มจากส่วนใดและนำไปจัดลำดับความสำคัญได้
- ป้องกันไม่ให้ระบบอ้างความแม่นยำเกินข้อมูลในช่วง Concept

## ผลตามมา

- Domain Model ต้องมี `special_feature_selections`, `allowance_items`, `allowance_version` และ `requires_expert_review`
- ต้องจัดทำ Allowance Library และกติกาป้องกันการคิดซ้ำกับ Material Level และ Complexity Factor
- Analytics ควรเก็บการเลือกฟีเจอร์เป็นหมวดที่ไม่ระบุตัวบุคคล เพื่อวิเคราะห์ความต้องการของตลาด
- ราคาของทั้ง 7 รายการต้องผ่านการตรวจรับก่อน Production

## ตัวเลือกที่ไม่เลือก

- ให้เลือกสเปกอุปกรณ์อย่างละเอียด: เกินความจำเป็นของ MVP และสร้างภาระสูง
- เก็บเป็นข้อความอย่างเดียวโดยไม่ประเมิน: ทำให้กรอบงบประมาณขาดรายการที่มีผลสูง
