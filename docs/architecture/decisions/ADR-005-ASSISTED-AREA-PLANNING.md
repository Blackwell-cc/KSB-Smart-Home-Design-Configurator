# ADR-005: ให้ระบบแนะนำพื้นที่จากจำนวนและประเภทห้อง

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-08-07
- ผู้ตัดสินใจ: Product Owner

## บริบท

ผู้ใช้ทั่วไปอาจยังไม่ทราบพื้นที่บ้านที่เหมาะสม แต่สามารถบอกจำนวนสมาชิก จำนวนห้อง และความต้องการใช้งานได้ หากบังคับให้กรอกพื้นที่เองตั้งแต่ต้น ผลประเมินอาจคลาดเคลื่อนหรือทำให้ผู้ใช้ออกจากระบบ อย่างไรก็ตาม การคำนวณราคาต้องใช้พื้นที่ก่อสร้าง ไม่ใช่เพียงพื้นที่ใช้สอย

## การตัดสินใจ

MVP จะใช้ Assisted Area Planning:

1. ผู้ใช้เลือกจำนวนและประเภทห้องด้วยตัวเลือกที่กดได้ง่าย
2. ผู้ใช้เลือกช่วงขนาดพื้นที่ที่ต้องการหรือระดับความกว้างของห้อง
3. ระบบคำนวณพื้นที่ใช้สอยแนะนำจาก Room Program และชุดมาตรฐานพื้นที่ห้องที่มีเวอร์ชัน
4. ระบบแปลงเป็นพื้นที่ก่อสร้างรวมโดยคำนึงถึงพื้นที่สัญจร ผนัง บันได ระเบียง เฉลียง ที่จอดรถ และพื้นที่ประกอบตามกติกาที่ KSB รับรอง
5. ผู้ใช้เห็นพื้นที่ทั้งสองชนิดและสามารถแก้ไขพื้นที่แนะนำได้ก่อนดูผล
6. Pricing Engine ใช้พื้นที่ก่อสร้างรวมเป็นฐานคำนวณราคา

## หลักการ UX

- ใช้ภาษาว่า “พื้นที่ที่เหมาะกับความต้องการของคุณ” แทนการทำให้ผู้ใช้รู้สึกว่าต้องรู้ศัพท์สถาปัตยกรรม
- แสดงเหตุผลสั้นๆ ว่าพื้นที่เพิ่มจากห้องใดหรือองค์ประกอบใด
- เมื่อผู้ใช้เพิ่มห้อง ระบบต้องอัปเดตพื้นที่แนะนำและงบประมาณอย่างคาดเดาได้
- หากผู้ใช้แก้พื้นที่ต่ำกว่าค่าที่รองรับ Room Program ระบบต้องเตือนและเสนอทางเลือก ไม่บล็อกทันทีโดยไม่มีคำอธิบาย
- ก่อนยืนยัน ให้ผู้ใช้เห็น “พื้นที่ใช้สอยโดยประมาณ” และ “พื้นที่ก่อสร้างที่ใช้ประเมินราคา” แยกกัน
- เก็บ Manual Override แยกจากค่าที่ระบบแนะนำ เพื่อใช้ตรวจสอบและปรับโมเดลภายหลัง

## หลักการคำนวณ

- ตารางขนาดห้องและค่าสัดส่วนพื้นที่ต้องมีเวอร์ชันและผู้อนุมัติ
- ห้ามใช้ตัวคูณ Usable Area เป็น CFA ตัวเดียวกับบ้านทุกประเภทโดยไม่มีการตรวจสอบ
- พื้นที่กึ่งภายนอกแต่ละประเภทสามารถใช้น้ำหนักต้นทุนต่างกันได้ แต่ค่าสัมประสิทธิ์ยังต้องให้สถาปนิก KSB ตรวจรับ
- หากข้อมูลไม่พอ ระบบต้องขยายช่วงราคาและลด Confidence Level แทนการแสดงตัวเลขที่ดูแม่นยำเกินจริง

## เหตุผล

- สอดคล้องกับเป้าหมาย “กดเลือกง่าย” ของผลิตภัณฑ์
- ช่วยผู้ใช้ที่ยังไม่มีแบบหรือไม่ทราบพื้นที่ที่เหมาะสม
- ลดการประเมินต่ำจากการลืมพื้นที่สัญจร บันได ระเบียง และพื้นที่ประกอบ
- ทำให้รายงานมี Room Program พร้อมนำไปสื่อสารกับสถาปนิกได้ทันที

## ผลตามมา

- Domain Model ต้องมี `room_program`, `recommended_usable_area`, `recommended_cfa`, `area_override` และ `area_rule_version`
- ต้องมี Room Area Library ที่ผ่านการตรวจรับก่อนเปิดใช้จริง
- ต้องทดสอบกรณีเพิ่มห้อง ลดพื้นที่ ย้อนกลับ และ Refresh แล้วค่าที่ผู้ใช้แก้ไม่หาย
- Full Report ต้องอธิบายที่มาของพื้นที่และแสดงคำเตือนเมื่อมี Manual Override ที่ไม่สอดคล้องกับ Room Program

## ตัวเลือกที่ไม่เลือก

- บังคับให้ผู้ใช้กรอกพื้นที่เอง: ใช้งานยากสำหรับผู้ที่ยังอยู่ช่วงเริ่มต้นและเสี่ยงต่อข้อมูลผิด
- เริ่มจากงบประมาณแล้วคำนวณพื้นที่อย่างเดียว: เหมาะเป็นเครื่องมือเสริมในอนาคต แต่ไม่สามารถเก็บ Requirement ห้องได้ครบเท่าแนวทางที่เลือก
