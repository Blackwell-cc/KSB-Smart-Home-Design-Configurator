# ADR-004: ขอบเขตค่าออกแบบและบริการวิชาชีพของ MVP

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-08-07
- ผู้ตัดสินใจ: Product Owner

## บริบท

ระบบต้องแสดงค่าออกแบบให้มีคุณค่าและโปร่งใส ผู้ใช้จึงต้องเข้าใจว่าช่วงราคาครอบคลุมบริการใด โดยเฉพาะต้องไม่ทำให้เข้าใจว่าค่าควบคุมงานก่อสร้างถูกรวมอยู่ในค่าออกแบบแล้ว

## การตัดสินใจ

ค่าออกแบบและบริการวิชาชีพที่ MVP ประเมินครอบคลุม:

1. งานออกแบบสถาปัตยกรรม
2. งานออกแบบโครงสร้าง
3. งานออกแบบระบบไฟฟ้า
4. งานออกแบบระบบสุขาภิบาล
5. เอกสารและแบบสำหรับยื่นขออนุญาตก่อสร้าง
6. แบบก่อสร้างตามขอบเขตมาตรฐานที่ KSB จะกำหนดรายละเอียดภายหลัง

รายการที่ไม่รวมในค่าออกแบบของ MVP:

1. ค่าควบคุมงานก่อสร้าง
2. ค่าออกแบบตกแต่งภายใน
3. ค่าออกแบบภูมิสถาปัตยกรรม
4. บริการหรือค่าใช้จ่ายอื่นที่ไม่ได้ระบุไว้ในขอบเขตข้างต้น

## หลักการนำเสนอ

- ใช้ข้อความ “ค่าออกแบบและบริการวิชาชีพโดยประมาณ” ไม่ใช้ “ค่าเขียนแบบ”
- แสดงรายการบริการที่รวมควบคู่กับช่วงราคา เพื่อสื่อคุณค่าของกระบวนการออกแบบและการประสานงาน
- แสดง “ค่าควบคุมงานก่อสร้าง: ยังไม่รวม” ในบริเวณที่เห็นได้ชัดทั้ง Full Report และ PDF
- หากมี CTA สำหรับควบคุมงาน ให้ใช้เป็นบริการแยก เช่น “ขอประเมินบริการควบคุมงาน” โดยไม่บวกเข้ายอดอัตโนมัติ
- ห้ามใช้คำว่า “ครบวงจร” หากบริบทอาจทำให้ผู้ใช้เข้าใจว่ารวมควบคุมงานหรือออกแบบภายใน

## เหตุผล

- ทำให้ช่วงค่าออกแบบสัมพันธ์กับงานที่ต้องผลิตจริงและตรวจสอบได้
- ช่วยอธิบายว่าค่าออกแบบมีมากกว่าการเขียนภาพหรือเขียนแบบ
- ป้องกันความเข้าใจผิดและข้อโต้แย้งเรื่องขอบเขตบริการในภายหลัง
- เปิดโอกาสให้ KSB เสนอบริการควบคุมงานเป็นบริการเพิ่มเติมอย่างโปร่งใส

## ผลตามมา

- Pricing Engine ต้องมี `design_scope_version` และไม่รวมค่าควบคุมงานในสูตรค่าออกแบบ
- Report ต้องมีส่วน Included / Not Included สำหรับค่าบริการวิชาชีพ
- ช่วงร้อยละค่าออกแบบใน Pricing Research Baseline ยังต้อง Calibrate กับราคาจริงของ KSB ภายใต้ขอบเขตนี้
- หาก KSB เปลี่ยนขอบเขตบริการ ต้องออก Design Scope เวอร์ชันใหม่ ห้ามแก้ความหมายย้อนหลัง
