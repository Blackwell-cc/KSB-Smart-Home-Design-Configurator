# ADR-009: ใช้ภาพ Curated สำหรับ Concept Preview ของ MVP

- สถานะ: ยอมรับแล้ว
- วันที่: 2026-08-07
- ผู้ตัดสินใจ: Product Owner

## บริบท

Concept Preview ต้องแสดงผลทันที สวยสม่ำเสมอ แชร์ได้ และสะท้อนภาพลักษณ์ KSB หากสร้างภาพด้วย AI แบบเรียลไทม์ ผลลัพธ์อาจช้า รูปแบบไม่สม่ำเสมอ หรือมีรายละเอียดทางสถาปัตยกรรมที่ไม่สมเหตุสมผลจนทำให้ผู้ใช้เข้าใจผิดว่าเป็นแบบเฉพาะโครงการ

## การตัดสินใจ

MVP จะใช้ Curated Concept Library ที่ KSB ตรวจรับแล้ว และจับคู่ภาพตามข้อมูล Configuration เช่น:

- House Style
- จำนวนชั้น
- Material Level หรือ Material Mood
- รูปแบบหลังคา
- ลักษณะช่องเปิดและความซับซ้อนของ Facade
- Special Feature ที่สามารถสื่อด้วยภาพได้

ระบบจะเลือกภาพที่ใกล้เคียงที่สุดด้วยกติกาที่กำหนดไว้ล่วงหน้าและมี Fallback เมื่อไม่มีภาพตรงทุกเงื่อนไข ไม่สร้างภาพ AI แบบเรียลไทม์ใน MVP

## หลักการ Content และความน่าเชื่อถือ

- ใช้ข้อความ “ภาพอ้างอิงทิศทางการออกแบบ” หรือ “Concept Inspiration”
- แสดงคำอธิบายว่าไม่ใช่แบบบ้าน แบบขออนุญาต แบบก่อสร้าง หรือคำรับรองว่าบ้านจริงจะเหมือนภาพ
- ห้ามใช้ข้อความที่ทำให้เข้าใจว่าภาพถูกออกแบบเฉพาะสำหรับที่ดินของผู้ใช้
- ภาพต้องผ่านการตรวจความสมเหตุสมผลด้านสถาปัตยกรรมและสอดคล้องกับ Positioning ของ KSB
- ภาพทุกภาพต้องมีสิทธิ์ใช้งาน แหล่งที่มา ผู้อนุมัติ และเวอร์ชันที่ตรวจสอบได้

## หลักการจับคู่และ Fallback

1. จับคู่ Style และจำนวนชั้นเป็นเงื่อนไขหลัก
2. ใช้ Material Mood หลังคา และ Facade เป็นเงื่อนไขจัดอันดับ
3. หากไม่มีภาพตรง ให้ลดเงื่อนไขรองตามลำดับที่กำหนด แต่ห้ามแสดงจำนวนชั้นผิด
4. หากไม่มีภาพที่ผ่านเกณฑ์ ให้ใช้ภาพ Placeholder ระดับแบรนด์พร้อมข้อความว่า Preview กำลังเตรียม ไม่สุ่มภาพที่ไม่ตรง
5. เก็บ `concept_asset_id`, `asset_version` และเหตุผลการจับคู่ใน Configuration Snapshot

## หลักการ UX, Accessibility และ Sharing

- โหลดภาพขนาดเหมาะสมตามอุปกรณ์และมี Fallback เมื่อไฟล์ภาพล้มเหลว
- ทุกภาพต้องมี Alt Text ที่สื่อความหมาย ไม่อธิบายองค์ประกอบเกินจริง
- Public Preview ใช้เฉพาะภาพที่ได้รับอนุญาตสำหรับการแชร์สาธารณะ
- Share Image ต้องไม่มี PII, Detailed Pricing, Full Requirement หรือ Private Notes
- หากภาพถูกยกเลิกในอนาคต ต้องรักษา Snapshot เดิมอย่างปลอดภัยหรือแทนด้วย Asset ที่ได้รับอนุมัติตามนโยบายเวอร์ชัน

## เหตุผล

- แสดงผลได้รวดเร็วและคาดเดาได้
- ควบคุมคุณภาพ ภาพลักษณ์ และความสมเหตุสมผลทางสถาปัตยกรรม
- ลดต้นทุนและความเสี่ยงจากการสร้างภาพแบบเรียลไทม์
- เหมาะกับ Organic Sharing เพราะสามารถตรวจสิทธิ์และองค์ประกอบของภาพก่อนเผยแพร่

## ผลตามมา

- ต้องมี Concept Asset Catalog และ Metadata ที่สอดคล้องกับตัวเลือกใน Configurator
- ต้องเตรียมภาพให้ครอบคลุม Style × จำนวนชั้นอย่างเพียงพอ โดยไม่จำเป็นต้องสร้างทุก Combination
- Analytics ควรเก็บ `concept_asset_id` เพื่อดูว่าภาพใดสัมพันธ์กับการแชร์หรือ Conversion
- การสร้างภาพ AI เฉพาะบุคคลเป็นฟีเจอร์หลัง MVP และต้องผ่าน Design Review ใหม่

## ตัวเลือกที่ไม่เลือก

- สร้างภาพ AI ทันทีใน Free Preview: มีความเฉพาะตัวแต่ควบคุมเวลา คุณภาพ ความสอดคล้อง และต้นทุนยากกว่า
- สร้างภาพ AI หลัง Soft Gate ใน MVP: เพิ่มขอบเขตระบบและความเสี่ยงโดยยังไม่จำเป็นต่อคุณค่าหลักของรายงาน
